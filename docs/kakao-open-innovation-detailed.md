## 0. 먼저 알아야 할 용어 (이것만 읽어도 절반은 이해된다)

| 용어 | 뜻 |
|---|---|
| **MCP** (Model Context Protocol) | AI 챗봇/에이전트가 외부 서비스의 기능을 표준 방식으로 호출하게 해주는 통신 규약. "AI용 USB-C 포트"라고 생각하면 된다. 예: 클로드에게 "홈페이지 만들어줘"라고 하면 클로드가 MCP를 통해 재밋의 제작 기능을 직접 실행한다. |
| **MCP 서버** | 위 규약으로 기능을 제공하는 쪽. **Zaemit은 이미 자체 MCP 서버를 운영 중**이고, 이것으로 사이트 생성·페이지 편집·상품 등록·예약 관리 등을 AI가 호출할 수 있다. 이 문서의 모든 협력 트랙은 "우리는 이미 이걸 갖고 있다"가 출발점이다. |
| **PlayMCP** | 카카오가 2025년 8월에 연 **MCP 서버 등록소(장터)**. 개발사가 자기 MCP 서버를 등록하면, 카카오 생태계의 AI 에이전트들이 그 기능을 쓸 수 있게 된다. 현재 카카오맵·멜론·선물하기 같은 카카오 자사 서비스 + 외부 서버 약 200개가 등록되어 있다. |
| **Kakao Tools** | PlayMCP 위에 있는 **사용자 노출 레이어**. PlayMCP가 개발자용 창고라면, Kakao Tools는 카카오톡 이용자가 실제로 만나는 진열대다. 위젯(카톡 대화창 안에 뜨는 그림·버튼이 있는 카드)을 지원하는 대신, MCP 표준 스펙을 더 엄격하게 요구한다. |
| **오픈클로(OpenClaw)** | 오픈소스 AI 에이전트. 2026년 5월부터 PlayMCP와 연동된다. 카카오 밖의 AI들도 PlayMCP 도구를 쓸 수 있게 문이 넓어졌다는 의미. |
| **카나나(Kanana)** | 카카오가 직접 만든 AI 모델 시리즈. 누구나 내려받아 쓸 수 있게 **오픈소스로 공개** 중이다(누적 40만 다운로드). |
| **LoRA** | 큰 AI 모델 전체를 다시 학습시키지 않고, 작은 부속만 덧붙여 학습시켜 특정 작업(예: 한국어 웹사이트 문안 생성)에 특화시키는 저비용 튜닝 기법. |
| **톡채널** | 소상공인용 카카오톡 공식 계정. 손님에게 광고 메시지를 보내는 통로. |
| **오픈이노베이션 / PoC** | 대기업이 스타트업과 하는 시범 협력. **PoC(Proof of Concept)는 "본계약 전의 시험 프로젝트"**라는 뜻으로, 여기서 끝나고 본계약으로 못 가는 경우가 절반 이상이다(7장에서 대응). |
| **Apollon** | Zaemit의 사이트 **자동 운영 AI**(사내명). 사이트를 만들고 끝이 아니라, 이후 콘텐츠 갱신·모니터링·재배포를 자동으로 돌리는 부분. Zaemit의 방어선이 되는 자산이다(7장 ③ 참고). |

## 1. 요약 — 왜 지금 카카오인가

카카오는 2026년을 "에이전틱 AI 원년"으로 선언하고, 외부 개발사가 들어올 문 두 개를 열어 놨다: **PlayMCP(등록소)와 Kakao Tools(카톡 노출 진열대)**.

그런데 문은 열렸는데 안이 비어 있다. 구체적으로 세 가지가 비어 있다.

**공백 1 — 결과물이 남는 도구가 없다.**
지금 PlayMCP에 등록된 도구들은 대부분 "맛집 추천해줘", "일정 잡아줘" 같은 **조회·추천형**이다. 대화가 끝나면 아무것도 남지 않는다. 반면 Zaemit 도구는 호출이 끝나면 **실제로 배포된 웹사이트**가 남는다. 사용자 입장에서 "AI가 뭔가 만들어줬다"는 체감이 가장 큰 종류의 도구인데, 이 카테고리가 통째로 비어 있다.

**공백 2 — 소상공인에게 홈페이지가 없다.**
카카오는 사장님에게 톡채널(단골 연락처), 메시지(광고 발송), 결제, 예약까지 다 줬다. 그런데 **손님이 그 메시지를 눌렀을 때 도착할 사장님의 홈페이지가 없다.** 대부분 톡채널 프로필 화면이 종착지인데, 프로필로는 메뉴 소개도 스토리텔링도 판매도 안 된다. 광고비를 태워도 착지 지점이 부실하니 전환율이 낮다. 카카오가 이걸 직접 만들어주기엔 사업 규모 대비 손이 너무 많이 가는 영역이고, Zaemit은 이걸 AI로 자동화한 회사다.

**공백 3 — 카나나로 돈 버는 회사가 없다.**
카카오는 자체 AI 모델 카나나를 오픈소스로 대량 배포했지만, "그 모델을 써서 실제 매출을 내는 상용 서비스" 레퍼런스가 없다. 오픈소스를 뿌린 조직이 사내 보고와 대외 홍보에서 가장 아쉬워하는 게 바로 이것이다. Zaemit이 카나나 기반으로 일부 기능을 돌리면, 카카오 AI 조직이 갖고 싶어하는 성과 지표를 우리가 만들어줄 수 있다.

이 세 공백을 **한 회사가 동시에** 채울 수 있는 곳은 사실상 Zaemit뿐이다. 웹 제작 자동화 + MCP 연동 + 자동 운영을 다 갖춘 회사가 드물기 때문이다.

### 트랙별 한 장 요약

| 트랙 | 협력 상대 | 우리가 주는 것 | 우리가 얻는 것 | 첫 행동 |
|---|---|---|---|---|
| 1. PlayMCP 등록 | 카카오 (플랫폼) | 카톡에서 쓸 수 있는 "홈페이지 제작" 도구 | 카톡 이용자 유통 채널, "카카오 생태계 안에 있다"는 명함 | 개발자 콘솔에서 지금 등록 (비용 0) |
| 2. 프로젝트 단골 | 카카오 상생 조직 | 소상공인 홈페이지 자동 생성 모듈·교육 | 사업자 계정 수만 개, 공공 레퍼런스 | 관계 구축 후 제안 (장기전) |
| 3. 카카오클라우드 | 카카오엔터프라이즈 | 클라우드 사용 실적, 공동 사례 | 인프라 파트너십, 마켓플레이스 판매 채널 | 파트너 프로그램 문의 |
| 4. 카나나 | 카카오 AI 조직 | 상용 매출 레퍼런스, 논문 공동 성과 | 기술 협력 명분, 추론 비용 절감 가능성 | 카나나 기반 LoRA 실험 |
| 5. 서비스 연동 | 카카오맵·싱크·페이 | 생성 사이트 전부에 카카오 부품 기본 탑재 | 연동 깊이 = 대체 불가능성 | 연동 개발 (독자 진행 가능) |

## 2. 트랙 1 — PlayMCP / Kakao Tools (유통 채널, 최우선)

### 이게 뭘 하자는 건가

지금 재밋 사이트를 만들려면 사용자가 zaemit.ai에 와야 한다. PlayMCP에 등록하면 **카카오톡 안에서** 사이트를 만들 수 있게 된다. 우리 서비스를 카카오톡이라는 국민 앱의 진열대에 올리는 것이다.

사용자가 겪는 장면은 이렇다:

```
[카카오톡 대화창]
사장님: "우리 카페 홈페이지 만들어줘. 이름은 소소상회, 성수동에 있어"
  ↓ 카카오 에이전트가 Zaemit MCP 도구를 호출
  ↓ (재밋이 사이트 구조를 짜고 페이지를 만들고 배포까지 완료 — 기존에 하던 그대로)
에이전트: [위젯 카드: 완성된 홈페이지 미리보기 이미지 + "사이트 보기" 버튼]
사장님: (버튼 클릭) → 실제 배포된 자기 홈페이지 도착
```

이후 "메뉴 사진 바꿔줘", "이번 주 공지 올려줘" 같은 운영 요청도 같은 대화창에서 이어진다. 이 운영 반복이 Apollon의 영역이고, **여기서 재방문과 구독이 발생한다.**

### 왜 우리가 이기는 판인가

| 비교 항목 | 기존 PlayMCP 도구 (약 200개) | Zaemit |
|---|---|---|
| 호출 후 남는 것 | 대화 답변 (휘발) | 배포된 웹사이트 (영구 자산) |
| 사용자가 다시 오는 이유 | 거의 없음 | 사이트 운영·수정할 때마다 |
| 엄격한 MCP 스펙 대응 | 대부분 단순 조회라 검증 안 됨 | 이미 상용 MCP 서버 운영 중 = 진입장벽이 우리 해자 |
| 위젯(시각 카드) 활용 | 텍스트 답변 위주라 쓸 게 없음 | 사이트 미리보기 = 위젯에 가장 어울리는 콘텐츠 |

특히 Kakao Tools가 요구하는 "더 엄격한 MCP 표준 스펙"은 신규 진입자에게는 장벽이지만, 이미 수백 개 도구를 상용 운영하는 우리에게는 **경쟁자를 걸러주는 필터**다.

### 타이밍 — 공모전은 놓쳤지만 오히려 기회

카카오 MCP 공모전 **AGENTIC PLAYER 10**의 일정:

- 접수: 2026.06.15 ~ 07.14 → **이미 마감** (우리는 이번 회차 참가 불가)
- 본선작 추가 개발: 7/30 ~ 8/27
- **카카오톡 안에서 이용자 공개 투표: 8/31 ~ 9/28** ← 여기가 핵심
- 시상식: 10/23, 총상금 2,700만 원 + 과기정통부 장관상

공모전 상금이 목적이 아니다. **투표 기간 4주 동안 카카오가 자기 돈으로 "카톡에서 MCP 도구 써보세요"라고 전 국민에게 홍보한다.** PlayMCP 등록은 공모전과 무관하게 상시 가능하므로, 지금 등록해 두면 그 홍보로 유입되는 트래픽이 우리 도구도 발견하게 된다. 남이 만든 무대에 무임승차하는 구조다. 투표 시작(8/31)까지 남은 기간이 등록·심사 데드라인이라고 봐야 한다.

### 실행 절차 (순서대로)

1. **카카오클라우드 계정 개설 + MCP 서버 Endpoint 생성** — 카카오는 PlayMCP 등록 서버를 자사 클라우드에서 돌리도록 요구한다(공모전 필수 요건이기도 했다). 기존 재밋 MCP 서버를 그대로 옮기는 게 아니라, 카카오클라우드 쪽에 접점(엔드포인트)을 하나 세우고 우리 백엔드로 연결하는 방식이 현실적이다.
2. **PlayMCP 개발자 콘솔 → '새로운 MCP 서버 등록' → 심사 제출.**
3. **심사 통과 후 공개 설정을 '전체 공개'로 직접 변경** — 기본값이 '나에게만 공개'라서, 이걸 안 바꾸면 등록하고도 아무에게도 안 보인다. 실수하기 쉬운 함정이라 체크리스트에 별도 항목으로 둔다.
4. **Kakao Tools 위젯 스펙 대응 개발** — 사이트 미리보기 썸네일을 위젯 카드로 내보내는 부분. 1~3과 병렬 진행 가능.

## 3. 트랙 2 — 프로젝트 단골 / 소상공인 (최대 매출 기회)

### 카카오가 이미 벌여놓은 판

카카오는 몇 년째 소상공인 디지털 전환 지원 사업을 대규모로 운영 중이다. 규모 감을 잡기 위한 숫자:

- **프로젝트 단골** (2022~): 전국 286개 전통시장·상점가에서 디지털 교육 진행. 톡채널 메시지 발송 지원금 누적 **334억 원**. 개별 사업자에게 상시 30만 원 지원금.
- **2026 상권 디지털 지원사업**: 전국 38개 상권 대상, 상권별 지원금 300만 원. **올해부터 "AI 활용 교육"이 커리큘럼에 신규 편성됐다** — 우리가 들어갈 자리가 방금 생겼다는 뜻이다.
- **단골가게** (2026 신규): 개별 가게를 브랜드 기획부터 판로·마케팅까지 밀착 지원. 첫 공모는 강원 F&B 10곳.

### 구조적 공백 — 한 사장님의 하루로 보면

성수동 카페 사장님이 카카오 지원을 다 받았다고 하자. 톡채널을 개설했고, 지원금 30만 원으로 단골 500명에게 신메뉴 광고 메시지를 보냈다. 손님이 메시지를 누른다. **어디에 도착하는가?** 톡채널 프로필이다. 메뉴판 사진 몇 장, 전화번호, 영업시간. 여기서 끝. 신메뉴 스토리도, 예약 유도도, 온라인 판매도 없다.

즉 카카오는 **광고 발송 장치(총)는 줬는데 착지 페이지(과녁)를 안 줬다.** 메시지 지원금 334억 원의 전환 효율이 착지 페이지 부재 때문에 깎이고 있는 셈이고, 이건 카카오 입장에서도 아까운 돈이다. Zaemit이 과녁을 만들어주면 카카오의 기존 투자 효율이 올라간다 — 이게 카카오를 설득하는 논리다.

### 구체적 제안 3종

1. **"톡채널 → 홈페이지" 원클릭 생성 모듈**: 사장님이 톡채널에 이미 입력해 둔 상호·업종·영업시간·메뉴·사진을 MCP로 읽어와서, 추가 입력 없이 홈페이지를 자동 생성한다. 사장님이 할 일은 버튼 한 번. 생성 후 운영(공지·메뉴 갱신)도 자동.
2. **AI 활용 교육에 재밋 실습 세션 편성**: 2026년 커리큘럼에 AI 교육이 신설됐으니, "AI로 우리 가게 홈페이지 만들기" 1시간 실습을 제안한다. 교육장에서 수강생 전원이 자기 가게 사이트를 들고 나가는 세션 — 교육 만족도 지표가 필요한 주최 측에 매력적이다.
3. **단골가게 선정 업체의 웹 파트 전담**: 이 프로그램은 브랜딩·패키지·판로를 지원하는데 웹사이트 항목만 없다. 빈 칸을 우리가 채우겠다고 제안한다.

### 수익 구조 — 반드시 지킬 원칙

이런 상생 프로그램의 함정은 **단가가 낮게 책정된다**는 것이다. "건당 얼마"(CPA, 만든 사이트 개수당 수수료) 방식으로 계약하면 박리다매 하청이 된다.

대신 이렇게 설계한다: **초기 생성은 무료 또는 저가로 열어주되, 생성된 계정의 소유권과 유료 전환(구독 결제) 권한은 Zaemit이 갖는다.** 카카오 프로그램은 우리에게 "고객 획득 비용이 0에 가까운 대량 유입 경로"이고, 매출은 그 뒤 구독 전환에서 나온다. 사업자 수만 명이 계정을 만들고 그중 일부만 유료 전환해도, 개별 영업으로는 불가능한 규모다.

카카오가 얻는 것: 디지털 전환 KPI 달성 + 메시지 광고 전환율 상승(= 광고 상품 가치 상승). 서로 남는 장사라는 그림이 성립한다.

## 4. 트랙 3 — 카카오클라우드 (가장 마찰 없는 상업 트랙)

### 배경

카카오는 "MCP 서버는 카카오클라우드에서 돌린다"를 표준으로 만들고 싶어한다. 공모전에서 카카오클라우드 엔드포인트 생성을 필수 요건으로 건 것이 그 증거다. 클라우드 사업부(카카오엔터프라이즈)는 AWS·네이버클라우드와 싸우는 처지라 **간판이 될 고객 사례**가 절실하고, 2026년 6월 kt cloud와 MOU를 맺는 등 파트너십에 적극적이다.

### 협력 포인트 3가지

1. **Apollon 운영 루프를 카카오클라우드 GPU에 배치** — Zaemit의 자동 운영 AI(Qwen3.6-35B-A3B 기반)가 도는 GPU 인프라를 카카오클라우드로 옮기거나 일부 배치하고, 이를 **공동 레퍼런스**(고객 사례 발표, 기술 블로그)로 만든다. 카카오엔터프라이즈는 "AI 스타트업이 우리 GPU에서 상용 서비스를 돌린다"는 영업 자료를 얻고, 우리는 인프라 크레딧·기술 지원·그룹 내 소개 라인을 얻는다.
2. **카카오클라우드 마켓플레이스 SaaS 입점** — 클라우드 장터에 재밋을 올리면, 카카오클라우드 영업 조직이 자기 고객(기업·공공)에게 재밋을 **대신 팔아주는** 재판매 채널이 생긴다.
3. **"MCP 서버 호스팅 베스트 프랙티스" 공동 문서/발표** — 기술 신뢰도와 인지도를 함께 올리는 저비용 홍보.

### 왜 이 트랙이 중요한가

상생 명분도, 심사도, 공모전도 필요 없는 **순수 B2B 거래**라서 마찰이 가장 적다. 그리고 트랙 1(PlayMCP)이 어차피 카카오클라우드 엔드포인트를 요구하므로, **이 트랙을 진행하면 트랙 1의 기술 전제조건이 자동으로 충족된다.** 하나의 작업이 두 트랙에 동시에 쓰이는 구조다.

## 5. 트랙 4 — 카나나 오픈소스 (기술 명분 + 학술 연결)

### 상황

카카오는 자체 AI 모델 카나나를 오픈소스로 계속 풀고 있다(2026.02~ 언어모델·멀티모달·가드레일, 7월 말 경량 모델 4종 추가, 누적 40만 다운로드). 행안부 'AI 국민비서' 같은 공공 사업에도 넣었다.

오픈소스를 이만큼 뿌린 조직의 다음 고민은 정해져 있다: **"다운로드는 많은데, 이걸로 실제 돈 버는 회사가 어디 있나?"** 경영진 보고와 대외 홍보에 쓸 상용 성공 사례가 필요한데, 아직 없다.

### 우리가 하는 일

Zaemit이 **카나나 경량 모델에 한국어 웹 생성·운영 특화 LoRA**(0장 용어 참고 — 모델 전체 재학습 없이 작은 부속만 튜닝)를 얹어, 재밋 파이프라인의 일부 작업(문안 생성, 콘텐츠 리프레시 등)을 카나나로 돌리는 실험을 한다. 성과가 나오면:

- 카카오: "카나나로 매출 내는 상용 서비스" 1호 레퍼런스 확보 — AI 조직이 가장 갖고 싶은 지표
- Zaemit: 카카오 AI 조직과의 직접 관계 + (경량 모델이므로) 추론 비용 절감 가능성

### 논문 연계

James가 준비 중인 **Retrieve–Verify–Escalate 프레임워크** SCI 논문이 이 트랙과 직결된다. 주제가 "경량 MoE 모델로 멀티스텝 에이전트 운영 루프를 안정화한 사례"인데, 카나나 경량 모델을 실험군에 포함시키면 카카오 연구 조직에 **공동 저자 참여를 제안할 근거**가 생긴다. 학술 협력은 사업 협력보다 문턱이 낮고, 일단 사람이 연결되면 사업 논의로 확장하는 우회 경로가 된다.

## 6. 트랙 5 — 카카오 서비스 연동 (맵·싱크·페이·톡채널)

### 방향

재밋이 생성하는 **모든 사이트에 카카오 부품을 기본값으로 심는다.** 개별 협상 없이 우리가 독자적으로 시작할 수 있고, 쌓이면 카카오와의 모든 협상에서 "우리는 이미 카카오 생태계에 트래픽을 공급하고 있다"는 카드가 된다.

| 카카오 서비스 | 재밋 사이트에서의 역할 | 카카오가 얻는 것 |
|---|---|---|
| 카카오맵 | 상점 사이트의 지도·위치·영업정보를 자동 주입 | 지도 데이터 활용도·노출 증가 |
| 카카오싱크 | 사이트 회원가입을 "카카오로 3초 가입"이 기본값 | 카카오 로그인 커버리지 확대 |
| 카카오페이 | 쇼핑 기능 설치 시 결제 수단 기본 탑재 | 결제 거래액(GMV) 증가 |
| 톡채널·예약·주문 | 사이트의 "예약하기"·"문의하기" 버튼이 톡채널로 연결 | 카톡 유입 루프 강화 |

### 카카오에게 파는 최종 그림

```
톡채널 메시지 → 사장님 홈페이지(재밋 제작·운영) → 예약/문의/결제는 다시 카카오로
```

손님이 **카카오 생태계 밖으로 한 발도 안 나가는 웹**을 재밋이 자동 양산한다는 스토리다. 카카오의 고질적 공포는 "이용자가 외부 웹으로 새는 것"인데, 재밋 사이트는 오히려 카카오로 되돌려 보낸다. 이 폐루프가 모든 카카오 미팅에서 반복할 핵심 한 문장이다.

## 7. 리스크 4가지와 방어 설계

### ① PoC로 끝나는 함정

오픈이노베이션의 절반 이상이 시범 프로젝트(PoC)만 하고 본계약 없이 끝난다. 대기업은 "스타트업과 협력했다"는 실적만으로 목적을 달성하기 때문이다.

**방어**: PoC 계약서에 처음부터 **전환 조건을 숫자로 명기**한다. 예: "PoC 기간 내 생성 사업자 계정 1,000개 + 30일 활성 사이트 40% 달성 시, 본계약(연간 최소 물량 N건, 매출 배분율 x:y) 체결" 식으로. 기준 미달이면 깔끔히 접고, 달성하면 자동으로 다음 단계로 가는 구조를 문서로 박는다.

### ② 카카오 채널 종속

카카오발 유입이 매출의 대부분이 되면, 재계약 때 조건을 카카오가 부른다. 일본 GMO Pepabo OEM(남의 브랜드로 우리 제품을 공급하는 계약)과 똑같은 역학이다.

**방어**: 일본 OEM 트랙을 일부러 병행 유지한다. "우리는 카카오 없어도 산다"는 사실 자체가 협상 테이블에서 가격 방어 카드가 된다.

### ③ 카카오의 내재화 ("그거 우리가 만들면 되잖아")

웹사이트 **생성**은 카카오가 "우리도 AI로 만들 수 있겠는데"라고 판단할 수 있는 영역이다. 협력하다가 배워서 직접 만들어버리는 리스크.

**방어**: 방어선을 생성이 아니라 **운영(Ops)**에 둔다. 사이트를 만드는 것은 한 번이지만, 수만 개 사이트의 콘텐츠 갱신·모니터링·재배포를 매일 돌리는 것은 카카오 입장에서 마진 안 나오는 귀찮은 롱테일 사업이라 내재화 유인이 없다. 그래서 대외 포지셔닝도 "AI Site **Builder**"(만들면 끝)가 아니라 "AI Site **Operator**"(계속 운영해주는 서비스)로 일관되게 가져간다.

### ④ 상생 프로그램의 저단가

**방어**: 3장에서 정리한 대로 — 진입 가격은 양보하되, **계정 소유권과 구독 전환 권한은 재밋 보유**를 계약의 양보 불가 조항으로 둔다.

순서에 논리가 있다: **1·2번은 심사나 인맥 없이 우리 손으로 지금 할 수 있는 것**이고, 이 실적("이미 PlayMCP에 등록된, 카카오클라우드 위에서 도는 서비스")이 3~5번 문을 두드릴 때의 명함이 된다.

### JCCEI × Kakao 오픈 그라운드 — 3번 경로 상세

카카오 그룹의 공식 스타트업 협력 공모 프로그램. 주관은 제주창조경제혁신센터(JCCEI, 전담 대기업이 카카오).

- 2026 회차: 3/23~4/10 모집 완료, 12월까지 운영 중 → **우리는 2027 회차(내년 3월 공고 예상) 목표**
- 참여 그룹사: 카카오·카카오모빌리티·카카오엔터테인먼트·카카오엔터프라이즈, 총 10개사 내외 선발
- 자격: 창업 7년 이내(신산업 10년) + **기투자 이력 또는 기술평가 T3 이상** → 위븐 충족
- 모집 분야에 **"산업 특화 SaaS" 명시** → 재밋이 정확히 부합
- 제출물: 사업자등록증 / 협업제안서 / IR 자료 / 투자계약서 또는 기술평가 확인서
- 선정 시: 그룹사와의 PoC 협업 기회 (2026.06 밋업에서 스타트업 26곳이 PoC 논의)

준비물 중 **협업제안서**가 사실상 이 문서의 최종 산출물이다. 트랙 1~5의 실행 실적이 제안서의 본문이 된다.
